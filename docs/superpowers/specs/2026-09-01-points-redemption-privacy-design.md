# LOOP 포인트 사용·관리자 설정·개인정보 보호 설계

## 목표
기존 방문 1회당 1P 적립 흐름을 유지하면서, 관리자가 포인트 혜택을 설정하고 고객이 포인트를 사용할 수 있게 한다. 관리자 화면은 PIN 9999로 보호하고, 개인정보 수집·이용 동의와 처리방침 안내를 키오스크 흐름에 포함한다.

## 핵심 사용자 흐름

### 신규 고객
1. 전화번호 입력
2. 필수 개인정보 수집·이용 동의 체크
3. 유입경로 선택
4. 포인트 적립
5. 완료 화면에서 현재 포인트 확인

### 기존 고객
1. 전화번호 입력
2. 기존 동의 기록 확인
3. 고객 선택 화면에서 현재 포인트 확인
4. `포인트 적립` 또는 `포인트 사용` 선택
5. 포인트 사용 시 혜택 선택 → 직원 PIN 확인 → 차감
6. 거래 이력 저장 및 완료 화면

### 관리자
1. 상단 `관리자 보기` 선택
2. PIN `9999` 입력
3. 성공 시 관리자 대시보드 진입
4. 포인트 정책에서 혜택명·필요 포인트 설정
5. 저장된 정책은 고객 포인트 사용 화면에 즉시 반영

## 개인정보 보호 설계

### 동의 UI
- 신규 고객은 필수 개인정보 수집·이용 동의를 직접 체크해야 한다.
- 체크박스는 사전 선택하지 않는다.
- 기존 고객은 이미 저장된 동의 버전이 현재 버전과 같으면 매 방문마다 재동의하지 않는다.
- 마케팅 수신 동의는 이번 범위에서 수집하지 않는다. 향후 추가 시 필수 동의와 분리한다.

### 고지 내용
- 수집·이용 목적: 멤버십 고객 식별, 방문 및 포인트 적립·사용 관리
- 수집 항목: 휴대전화번호
- 보유·이용 기간: 회원 탈퇴 또는 동의 철회 시까지. 관계 법령상 보존 의무가 있는 경우 해당 기간 동안 분리 보관
- 동의 거부 권리: 동의하지 않을 수 있으나 멤버십 포인트 서비스 이용이 제한될 수 있음
- 개인정보 처리방침 보기 링크/모달 제공

### 동의 기록
Customers 데이터에 아래 필드를 추가한다.
- `privacyConsentAt`: 동의 일시(ISO 문자열)
- `privacyConsentVersion`: 동의 문안 버전

전화번호와 함께 동의 여부를 추적할 수 있어야 하며, 동의 버전이 바뀌면 신규 문안에 다시 동의하도록 한다.

## 포인트 정책
관리자가 여러 혜택을 정의할 수 있다.

```ts
type Reward = {
  id: string
  name: string
  points: number
  enabled: boolean
}
```

기본 혜택:
- 10P → 아메리카노 1잔
- 20P → 3,000원 할인

관리자 화면에서 혜택명과 필요 포인트를 수정하고 활성/비활성 할 수 있다.

## 거래 모델
적립과 사용 모두 거래 이력으로 저장한다.

```ts
type PointTransaction = {
  date: string
  phone: string
  type: 'EARN' | 'REDEEM'
  delta: number
  balanceBefore: number
  balanceAfter: number
  description: string
}
```

Google Sheets에는 `Transactions` 시트를 사용한다.

헤더:
`date | phone | type | delta | balanceBefore | balanceAfter | description`

## 포인트 사용 안전장치
- 보유 포인트보다 큰 혜택은 선택 불가
- 사용 확정 전에 직원 PIN `9999` 확인
- 연속 탭 중복 차감 방지를 위한 동기식 잠금 유지
- 서버에서도 현재 잔액을 다시 읽고 부족하면 `INSUFFICIENT_POINTS` 반환
- 모든 성공 차감은 거래 이력에 남김

## 관리자 PIN
현재 요구사항에 따라 기본 PIN은 `9999`다.
- 고객 UI에 PIN이 노출되지 않는다.
- 서버 비밀키가 아닌 단순 UI 진입 보호 목적이다.
- 향후 실제 상용 운영 시 환경변수 기반 PIN 또는 관리자 인증으로 교체할 수 있도록 상수 분리한다.

## 데이터 호환성
기존 Customers 시트의 `id, phone, source, visits, points, lastVisit` 6개 열은 유지하고 뒤에 동의 열을 추가한다. 기존 고객의 동의 필드는 빈 값으로 읽히며, 첫 방문 시 재동의를 받는다.

## 오류 처리
- 잘못된 전화번호: `INVALID_PHONE`
- 동의 없음 신규가입: `CONSENT_REQUIRED`
- 존재하지 않는 고객의 포인트 사용: `CUSTOMER_NOT_FOUND`
- 잔액 부족: `INSUFFICIENT_POINTS`
- 잘못된 사용 포인트: `INVALID_POINTS`
- Google Sheets 미설정: 기존 `GOOGLE_SHEETS_NOT_CONFIGURED`

## 법적 설계 참고
현재 개인정보 보호법 제15조는 동의를 받을 때 수집·이용 목적, 항목, 보유·이용 기간, 동의 거부 권리 및 불이익을 알리도록 하고 있다. 제22조와 시행령 제17조는 동의 사항을 구분하고 정보주체가 자유롭게 동의 여부를 결정·표시할 수 있는 방법을 제공하도록 한다. 따라서 사전 체크된 필수 동의 대신 신규 고객이 직접 체크하는 방식을 사용한다.

이 문서는 제품 구현을 위한 일반적인 개인정보 보호 설계이며 개별 사업자의 최종 법률 자문을 대체하지 않는다.
