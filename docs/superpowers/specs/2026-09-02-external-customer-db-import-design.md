# 외부 고객 DB 가져오기 설계

## 목적

기존 멤버십·포인트 시스템에서 받은 `.xlsx`, `.xls`, `.csv` 파일을 LOOP 관리자 화면에서 읽어 현재 LOOP 데이터 구조에 맞게 안전하게 변환·이전한다.

목표는 다음과 같다.

- 원본 엑셀을 사람이 미리 가공하지 않아도 된다.
- 한 파일 안의 모든 시트를 분석한다.
- 업체마다 다른 시트명·컬럼명을 자동 추정하고 관리자가 최종 확인한다.
- 방문포인트·도장·결제포인트를 절대 자동 합산/환산하지 않는다.
- 기존 LOOP 고객과 중복되면 관리자 확인 전에는 반영하지 않는다.
- 실제 날짜가 없는 방문/포인트 이력은 임의 생성하지 않는다.
- 현재 고정한 Google Sheet 탭 구조는 바꾸지 않는다.
- LOOP에 저장할 수 없는 원본 컬럼도 조용히 버리지 않고 `미지원/제외 정보`로 보여준다.

## 고정 Google Sheet 구조

Import 기능은 아래 탭과 순서를 변경하지 않는다.

1. 대시보드
2. 고객_목록
3. 고객_방문기록
4. 고객_재방문설문
5. 포인트_전체거래내역
6. 포인트_방문적립내역
7. 포인트_도장적립내역
8. 포인트_결제적립내역
9. 설정_방문포인트혜택
10. 설정_결제포인트혜택
11. 설정_적립방식

원본 파일이나 Import 임시 시트를 Google Sheet에 추가하지 않는다.

## 선택한 방식

**브라우저 자동 분석 + 관리자 확인 + 서버 재검증** 방식으로 구현한다.

원본 파일은 관리자 브라우저에서 파싱한다. 브라우저가 정규화된 데이터만 서버에 전달하고, 서버는 관리자 PIN과 데이터 규칙을 다시 검증한 뒤 기존 Google Sheet에 반영한다.

완전 자동 변환은 하지 않는다. `포인트`, `잔액`, `적립금`처럼 의미가 애매하거나 기존 LOOP 고객과 충돌하는 데이터는 반드시 사람 확인을 거친다.

## 관리자 Import Wizard

관리자 대시보드에 `기존 고객 DB 가져오기` 기능을 추가한다.

진행 단계:

`1 파일 → 2 시트 → 3 컬럼 → 4 중복 → 5 최종검토`

### 1. 파일

지원 형식:

- `.xlsx`
- `.xls`
- `.csv`

초기 제한:

- 최대 10MB
- 최대 20개 시트
- 전체 최대 50,000행

파일을 선택해도 즉시 DB는 수정되지 않는다.

### 2. 모든 시트 분석

파일 안 모든 시트를 표시한다.

각 시트의 역할은 자동 추정 후 관리자가 수정할 수 있다.

- 고객정보
- 방문이력
- 포인트이력
- 제외

예:

| 원본 시트 | LOOP 제안 |
| --- | --- |
| 회원목록 | 고객정보 |
| 이용내역 | 방문이력 |
| 적립내역 | 포인트이력 |
| 안내 | 제외 |

각 시트는 행 수, 헤더, 샘플 행을 함께 보여준다.

## 시트 간 고객 연결

외부 파일은 모든 시트에 전화번호가 존재한다는 보장이 없다.

예:

`회원목록`

| 회원번호 | 휴대폰 | 방문수 |
| --- | --- | ---: |
| A1001 | 010-1234-5678 | 12 |

`방문내역`

| 회원번호 | 방문일 |
| --- | --- |
| A1001 | 2026-08-20 |

이 경우 고객정보 시트의 `회원번호`를 **외부 고객키**로 지정하고, 방문/포인트 시트의 같은 키와 연결해서 최종 전화번호를 찾는다.

지원 연결 방식:

1. 전화번호 직접 연결
2. 외부 회원ID/회원번호로 고객정보 시트와 JOIN

외부 회원번호는 LOOP의 실제 고객ID로 저장하지 않는다. Import 중 시트 연결에만 사용한다.

고객정보에도 전화번호가 없어서 LOOP 고객과 연결할 수 없는 행은 오류로 분류한다.

## 컬럼 자동 매핑

### 고객정보

지원 LOOP 필드:

- 전화번호
- 외부 고객키
- 방문횟수
- 방문포인트
- 도장
- 결제포인트
- 최근방문일
- 최초유입경로

### 방문이력

- 전화번호 또는 외부 고객키
- 방문일
- 결제금액
- 유입경로

### 포인트이력

- 전화번호 또는 외부 고객키
- 날짜
- 적립/차감량
- 거래구분
- 잔액
- 내용
- 포인트 종류

흔한 컬럼명을 자동 인식한다.

예:

- 전화번호: `전화번호`, `휴대폰`, `핸드폰`, `휴대전화`, `mobile`, `phone`, `tel`
- 외부키: `회원번호`, `회원ID`, `customer id`, `member id`
- 방문횟수: `방문수`, `방문횟수`, `누적방문`, `visits`
- 포인트: `포인트`, `적립금`, `마일리지`, `point`, `points`, `balance`
- 최근방문: `최근방문`, `마지막방문`, `last visit`

자동 추정에는 `자동 인식` 배지를 표시하고, 신뢰도가 낮은 매핑은 `확인 필요`로 표시한다.

## 미지원 원본 정보

현재 LOOP 고객 구조에 없는 필드는 자동 저장하지 않는다.

예:

- 고객명
- 이메일
- 생년월일
- 주소
- 메모
- 원본 시스템 전용 등급

이런 컬럼은 매핑 화면에서 `LOOP 저장 위치 없음 · 제외`로 명확히 보여준다.

사용자는 어떤 정보가 이전되지 않는지 최종 실행 전에 알 수 있어야 한다.

## 포인트 종류 매핑

외부 `포인트`, `잔액`, `적립금` 컬럼은 반드시 다음 중 하나를 지정한다.

- 방문포인트
- 도장
- 결제포인트
- 가져오지 않음

자동 추정은 추천일 뿐 최종 결정은 관리자에게 있다.

현재 활성 적립방식과 다른 종류로 가져오는 경우 다음과 같이 경고한다.

> 현재 매장은 도장 쿠폰을 사용 중입니다. 이 잔액은 방문포인트로 별도 보존되며 도장으로 환산되지 않습니다.

## 정규화 규칙

### 전화번호

- 숫자가 아닌 문자를 제거한다.
- 기존 `normalizePhone()` 규칙을 사용한다.
- 정상 휴대전화번호로 판단할 수 없으면 오류 행으로 분류한다.

### 방문횟수와 잔액

- 0 이상의 정수만 허용한다.
- 빈 값은 `값 없음`으로 유지한다.
- 빈 값을 0으로 간주해 기존 값을 덮어쓰지 않는다.
- 음수 보유잔액은 오류 처리한다.

### 날짜

인식 대상:

- Excel date serial
- `YYYY-MM-DD`
- `YYYY.MM.DD`
- `YYYY/MM/DD`
- 일반적인 한국식 날짜

파싱할 수 없는 값은 해당 필드의 오류로 표시한다.

## 과거 방문 처리

실제 방문 날짜가 있으면 `고객_방문기록`에 과거 이력으로 저장한다.

실제 날짜 없이 `총 방문 12회`만 있으면:

- `고객_목록.방문횟수 = 12` 반영
- 가짜 방문 12건은 생성하지 않음

`최근방문일`만 있으면 고객 요약값에만 사용한다.

## 과거 포인트 처리

### 현재 잔액만 있는 경우

예: `보유 방문포인트 = 8P`

`고객_목록`에 8P를 반영하고 Import 실행일 기준으로 초기 이전 기록을 남긴다.

방문포인트:

- `포인트_전체거래내역`: `ADJUST`, `기존 시스템 DB 이전`
- `포인트_방문적립내역`: 동일 의미의 초기 원장

도장:

- `포인트_도장적립내역`에 초기 이전 기록

결제포인트:

- `포인트_결제적립내역`에 초기 이전 기록

없는 과거 적립 날짜는 만들지 않는다.

### 실제 거래 이력이 있는 경우

날짜와 변동량이 충분하면 실제 이력을 가져온다.

거래 이력으로 계산한 잔액과 고객정보 시트의 현재 잔액이 다르면 관리자에게 보여준다.

선택지:

- 이력 기준
- 현재 잔액 기준으로 마지막 조정 기록 추가
- 고객 제외

기본 추천은 **현재 잔액 기준으로 마지막 조정 기록 추가**다.

## 기존 LOOP 고객 중복 정책

주 중복키는 정규화된 전화번호다.

자동 합산하지 않는다.

예:

| 항목 | 현재 LOOP | 외부 DB |
| --- | ---: | ---: |
| 방문횟수 | 3 | 12 |
| 방문포인트 | 5P | 8P |
| 도장 | 1 | 없음 |
| 결제포인트 | 0P | 없음 |
| 최근방문일 | 2026-08-01 | 2026-08-20 |

중복 고객마다 선택:

1. 기존 LOOP 유지
2. 외부 DB 값으로 갱신
3. 항목별 직접 선택

항목별 직접 선택 대상:

- 방문횟수
- 방문포인트
- 도장
- 결제포인트
- 최근방문일
- 최초유입경로

`현재 + 외부 값 자동 합산`은 제공하지 않는다.

## 신규 Import 고객

기존 LOOP에 없는 전화번호는 신규 고객으로 만든다.

- LOOP에서 새 고객ID 생성
- 외부 회원번호는 LOOP 고객ID로 사용하지 않음
- 기존 방문횟수와 잔액 보존
- 개인정보동의일시/버전은 비움
- 다음 실제 LOOP 이용 시 현재 개인정보 동의를 1회 다시 받음

Import 자체가 개인정보 동의 기록을 생성하지 않는다.

## 최종 미리보기

반영 전에 반드시 전체 요약을 보여준다.

예:

- 총 분석 행 1,352
- 신규 고객 1,102
- 기존 고객 중복 84
- 제외 153
- 오류 13
- 방문이력 8,241건
- 방문포인트 이전 18,420P
- 도장 이전 324개
- 결제포인트 이전 2,850,000P

추가 표시:

- 오류 행과 이유
- 미지원/제외 컬럼
- 포인트 유형별 합계
- 현재 잔액과 이력 불일치 고객
- 아직 결정하지 않은 중복 고객 수

정상 데이터만 선택적으로 Import할 수 있다.

## 실행 조건

`DB 가져오기 실행`은 아래 조건을 모두 만족해야 활성화한다.

- 모든 사용 시트 역할 확정
- 전화번호 또는 외부 고객키 연결 확정
- 애매한 포인트 컬럼 종류 확정
- 모든 중복 고객 처리 결정
- 치명적 오류 없음
- `위 내용을 확인했습니다` 체크

서버는 최종 요청에서 관리자 PIN을 다시 검증한다.

## API

새 경로:

`POST /api/admin/import`

브라우저는 **원본 파일 자체가 아닌 정규화된 데이터 + 관리자 선택 결과**를 보낸다.

서버는 다음을 다시 검증한다.

- 관리자 PIN
- 전화번호
- 숫자/날짜
- 중복 정책
- 잔액 종류
- 최종 확인 여부
- Import payload 크기

서버는 브라우저가 계산한 합계 값을 신뢰하지 않고 직접 다시 계산한다.

## 재실행 및 중복 방지

각 Import에는 `importId`와 payload hash를 부여한다.

Google Sheet 탭을 추가하지 않고 **Spreadsheet Developer Metadata**에 완료된 Import 식별자를 저장하는 방식을 우선 사용한다.

- 동일 `importId/hash`가 완료 상태면 재실행하지 않는다.
- Import 원장 description에도 식별 가능한 Import 참조를 남겨 감사 가능성을 높인다.
- 요청 전 현재 고객 스냅샷을 재조회하고, 미리보기 이후 고객 값이 변경됐으면 해당 중복 결정을 다시 요구한다.

Developer Metadata 사용이 실제 Google Sheets API 권한/제약상 불가능한 경우에는 구현 단계에서 동일 payload 재전송을 거부하고 현재 상태 재검증을 강제하는 보수적 방식으로 대체한다. 새 탭은 만들지 않는다.

## Google Sheets 반영

`lib/sheets.ts`의 `SHEET_LAYOUT`은 수정하지 않는다.

추가할 bulk 함수:

- 고객 일괄 갱신
- 방문기록 일괄 추가
- 전체거래내역 일괄 추가
- 방문포인트 원장 일괄 추가
- 도장 원장 일괄 추가
- 결제포인트 원장 일괄 추가

가능한 쓰기는 batch 요청으로 묶는다.

Google Sheets가 일반 DB 트랜잭션과 동일하지 않으므로 서버는 쓰기 직전 현재 상태를 재검증하고, 완료 후 다시 읽어 결과 수량과 잔액을 확인한다.

## 파일 파서

브라우저에서 Excel/CSV를 읽을 수 있는 라이브러리를 사용한다.

필수 조건:

- xlsx 지원
- legacy xls 지원
- csv 지원 또는 CSV 별도 파서 병행
- 서버에 원본 파일을 저장할 필요가 없음

구현 시 현재 유지보수 상태와 보안 이슈를 확인하고 버전을 고정한다.

## 개인정보 및 보안

- 관리자 인증 후에만 Import UI 노출
- Import API에서 PIN 재검증
- 원본 파일 서버 영구 저장 금지
- 서버 로그에 전화번호/고객 원본행 출력 금지
- 관리자 일반 고객 목록은 기존처럼 마스킹 유지
- Import 미리보기의 원본 전화번호는 업로드한 브라우저 세션 안에서만 사용
- Import 고객에게 개인정보 동의 이력을 위조 생성하지 않음

### 회귀 테스트

- 방문 1P 적립
- 도장 적립/사용
- 결제포인트 적립/사용
- 고객 상세/조정
- 한글 시트 구조
- 대시보드 첫 탭 유지

## 완료 기준

1. 한 파일에 여러 시트가 있어도 모두 표시된다.
2. 고객/방문/포인트/제외 역할을 각각 지정할 수 있다.
3. 여러 시트가 외부 회원번호로만 연결돼도 고객 전화번호와 JOIN할 수 있다.
4. 흔한 컬럼은 자동 매핑되고 관리자가 수정할 수 있다.
5. 방문포인트/도장/결제포인트를 직접 지정할 수 있다.
6. LOOP에 저장되지 않는 컬럼을 Import 전에 확인할 수 있다.
7. 기존 고객은 자동 합산되지 않는다.
8. 기존 유지/외부값/항목별 선택이 가능하다.
9. 실제 날짜가 없는 방문 이력을 가짜로 만들지 않는다.
10. 현재 잔액만 있으면 `기존 시스템 DB 이전` 기준 기록을 만든다.
11. Import 후 고객의 방문횟수와 잔액이 정상 조회된다.
12. Import 고객은 다음 실제 이용 시 개인정보 동의를 다시 받는다.
13. 현재 Google Sheet 탭 이름과 순서가 그대로 유지된다.
14. 동일 Import 재실행으로 이력이 중복 생성되지 않는다.
15. `npm test`와 `npm run build`가 성공한다.
16. Vercel Preview 검증 후 main 병합 및 Production SHA/READY를 확인한다.
