# 관리자 고객 상세·포인트 조정 설계

## 목표

관리자 화면에서 고객을 클릭하면 해당 고객의 포인트 전체 이력을 확인하고, 현재 포인트를 원하는 최종값으로 조정할 수 있게 한다. 조정은 과거 거래를 덮어쓰지 않고 `ADJUST` 거래로 차액만 기록한다. 동시에 고객/관리자 화면의 강제 줄바꿈을 줄이고 PC·태블릿·모바일에서 자연스럽게 읽히도록 반응형 타이포그래피를 개선한다.

## 관리자 고객 상세 흐름

- 관리자 고객 행 전체를 클릭 가능하게 한다.
- 클릭 시 서버에 관리자 PIN과 `customerId`를 보내 상세 정보를 조회한다.
- 상세 응답은 마스킹 전화번호, 유입경로, 방문 수, 현재 포인트, 최근 방문일, 해당 고객의 전체 포인트 거래내역을 포함한다.
- 전체 원문 전화번호는 브라우저에 반환하지 않는다.
- 거래내역은 최신순으로 표시하며 `적립`, `사용`, `관리자 조정`으로 구분한다.

## 포인트 조정 방식

- 관리자는 팝업에서 최종 포인트 정수값을 입력한다.
- 서버는 현재 포인트와 목표 포인트의 차이를 계산한다.
- 예: 10P → 15P는 `ADJUST +5`, 10P → 7P는 `ADJUST -3`으로 기록한다.
- 목표값은 0 이상의 정수만 허용한다.
- 변경 전/후 잔액과 설명 `관리자 포인트 조정`을 Transactions 시트에 남긴다.
- 기존 `EARN`/`REDEEM` 거래와 방문 기록은 수정하지 않는다.
- 조정 완료 후 고객 목록과 팝업 잔액/이력을 즉시 갱신한다.

## API 및 저장 구조

- `PointTransaction.type`에 `ADJUST`를 추가한다.
- `lib/member-service.ts`에 `adjustCustomerPoints(customers, customerId, targetPoints, now)` 순수 함수를 추가한다.
- `lib/sheets.ts`에 고객 전화번호 기준 Transactions 전체를 읽는 함수를 추가한다.
- `/api/members`에 관리자 전용 `detail`과 `adjust` 액션을 추가한다.
- `detail`/`adjust` 모두 관리자 PIN을 서버에서 검증한다.
- `adjust`는 Customers 잔액을 먼저 저장하고 ADJUST transaction을 기록한다.

## UI

- 고객 행 클릭 시 데스크톱에서는 중앙 모달, 모바일에서는 화면 폭에 맞는 큰 시트형 모달로 표시한다.
- 상단 요약: 마스킹 번호, 현재 포인트, 방문 수, 최근 방문일, 유입경로.
- 중단: 최종 포인트 입력 + `포인트 수정` 버튼 + 변경 예정 차액 미리보기.
- 하단: 전체 포인트 내역 타임라인/리스트.
- 삭제 버튼 클릭은 상세 팝업 열기와 이벤트가 겹치지 않게 `stopPropagation()` 처리한다.

## 반응형 줄바꿈

- 제목/본문의 불필요한 `<br>`를 제거하고 CSS 기반 자연 줄바꿈을 사용한다.
- 주요 제목/설명에 `word-break: keep-all`, `overflow-wrap: break-word`, 지원 브라우저에서 `text-wrap: balance`를 적용한다.
- 컨테이너 최대 폭과 `clamp()` 폰트 크기를 PC/태블릿/모바일에 맞춰 조정한다.
- 전화번호·포인트·버튼처럼 끊기면 안 되는 짧은 정보는 `white-space: nowrap`을 유지한다.
