# LOOP Membership

매장 태블릿에서 전화번호 기반 멤버십을 운영하고, 관리자가 고객·재방문·적립 정책을 관리하는 Next.js + Google Sheets 앱입니다.

## 주요 기능

- 관리자가 적립 방식을 선택: `방문 1P` / `도장 쿠폰` / `결제금액 % 적립`
- 적립 방식별 잔액과 원장을 서로 분리해 저장하고, 방식을 바꿨다가 돌아와도 기존 잔액 보존
- 결제금액 적립 방식에서 다른 방식으로 변경할 때 기존 결제 포인트가 있으면 확인 경고 필수
- 도장 쿠폰 시각화, 쿠폰 완성 혜택 및 직원 PIN 사용 확인
- 결제금액 × 설정 비율의 포인트를 계산하며 소수점은 버림
- 신규 고객 유입경로 설문 + 재방문 고객의 업종별 이유 설문
- 재방문 설문은 업종 프리셋을 제공하고 관리자가 최대 6개 문구·감사 메시지를 수정 가능
- 관리자 KPI 카드 클릭 시 날짜별 선 그래프 분석
- 고객별 방문 포인트 내역 확인 및 관리자 포인트 조정
- 관리자 목록에서는 전화번호를 마스킹해 전달
- 개인정보 삭제 요청 시 관련 방문·거래·각 적립 원장·재방문 이유 기록 함께 삭제
- 빠른 연속 탭 중복 요청 방지

## 실행

```bash
npm install
npm run dev
```

## 환경변수

```env
GOOGLE_SERVICE_ACCOUNT_EMAIL=
GOOGLE_PRIVATE_KEY=
GOOGLE_SHEET_ID=
LOOP_AUTH_SECRET=
LOOP_ADMIN_PIN=9999
```

운영 환경에서는 `LOOP_ADMIN_PIN`을 Vercel 환경변수에서 별도로 변경하세요.
업체별 시트 연결을 사용할 때는 `LOOP_AUTH_SECRET`에 충분히 긴 임의의 비밀 문자열을 추가하세요.

## Google Sheets 구성

서비스 계정을 Google Sheet의 **편집자**로 공유하면 필요한 시트가 자동으로 생성됩니다.

시트는 매장 운영자가 바로 이해할 수 있도록 한글 이름과 한글 헤더를 사용합니다. 기존 버전에서 `Customers`, `Visits`, `Settings` 등 영문 탭을 사용하고 있었다면 **새 시트로 복사하지 않고 기존 sheetId의 탭 이름만 자동으로 변경**하므로 기존 데이터 행은 그대로 유지됩니다.

탭 색상도 용도별로 구분합니다.

### 고객 관련

- `고객_목록` — 고객ID, 전화번호, 최초 유입경로, 방문횟수, 방문포인트, 최근방문일, 개인정보 동의, 도장개수, 결제포인트
- `고객_방문기록` — 날짜별 방문 기록
- `고객_재방문설문` — 방문 회차별 재방문 사유 응답

`고객_목록`의 주요 잔액은 서로 분리되어 있습니다.

- `방문포인트`: 방문 1P 방식 잔액
- `도장개수`: 도장 방식 잔액
- `결제포인트`: 결제금액 방식 잔액

### 포인트 기록

- `포인트_전체거래내역` — 방문 포인트 적립·사용·관리자 조정 감사 기록
- `포인트_방문적립내역` — 방문 포인트 전용 원장
- `포인트_도장적립내역` — 도장 적립·사용 전용 원장
- `포인트_결제적립내역` — 결제금액, 적립률, 적립 포인트, 전후 잔액을 포함한 결제 포인트 전용 원장

### 설정 관련

- `설정_방문포인트혜택` — 방문 포인트 사용 혜택
- `설정_결제포인트혜택` — 결제 포인트 사용 혜택
- `설정_적립방식` — 현재 적립 방식, 결제 적립률, 도장 목표, 도장 혜택, 업종, 재방문 설문 문항
- `설정_매장연결` — 업체명, 매장 연결코드, 사용상태, 앱 표시명

### 업체별 시트 연결

업체마다 자신의 Google Sheets를 하나씩 사용합니다.

1. 업체의 시트를 LOOP 서비스 계정 이메일에 **편집자**로 공유합니다.
2. 앱이 시트에 처음 접근하면 `설정_매장연결` 탭이 자동으로 생성됩니다.
3. `설정_매장연결`의 2행에 업체명, 연결코드, `정상`, 앱 표시명을 입력합니다.
4. Android APK 첫 화면에서 해당 Google Sheets 주소와 연결코드를 한 번 입력합니다.
5. 연결이 완료되면 기기에 토큰이 저장되어 다음 실행부터 자동으로 연결됩니다.

구글시트 주소 자체는 비밀번호가 아닙니다. 실제 연결은 시트 접근 권한과 `설정_매장연결`의 연결코드가 모두 맞아야 완료됩니다. APK에는 Google 서비스 계정 이메일이나 Private Key를 넣지 않습니다.

앱이 시트에 처음 접근할 때 관리 탭을 **고객 → 포인트 기록 → 설정** 순서로 정리하고, 각 그룹에 서로 다른 탭 색상을 적용합니다. 1행의 컬럼명도 자동으로 한글화되며 2행 이하의 기존 데이터는 유지합니다.

## 적립 방식 전환 원칙

세 잔액은 자동으로 변환하거나 합산하지 않습니다.

예를 들어 한 고객이 방문 포인트 `7P`, 도장 `4개`, 결제 포인트 `2,350P`를 보유한 상태에서 도장 방식으로 변경해도 나머지 잔액은 그대로 보존됩니다. 나중에 결제금액 적립 방식으로 돌아오면 `2,350P`에서 이어집니다.

결제금액 적립 방식에서 다른 방식으로 나갈 때 결제 포인트 잔액이 남아 있으면 서버에서도 확인 플래그를 요구해 실수로 전환하지 않도록 합니다.

## 고객 흐름

1. 전화번호 입력 및 가입 여부 확인
2. 신규·재동의 대상 고객만 개인정보 수집·이용 동의
3. 신규 고객은 최초 유입경로 선택
4. 재방문 고객은 업종별 재방문 이유 설문을 선택하거나 건너뜀
5. 현재 관리자 설정에 따라 방문 포인트 / 도장 / 결제금액 적립 진행
6. 혜택 사용 시 직원 관리자 PIN 확인
7. 완료 후 약 12초 뒤 다음 고객 화면으로 복귀

## 관리자 흐름

관리자는 4자리 PIN 인증 후 다음 기능을 사용할 수 있습니다.

- 전체 고객 / 누적 방문 / 재방문 / 현재 적립방식 잔액 KPI 확인
- KPI 클릭 후 30일 / 90일 / 전체 날짜별 선 그래프 확인
- 적립 방식 선택 및 세부 설정
- 업종별 재방문 설문 프리셋 선택 후 최대 6개 문항·감사 문구 수정
- 방문·결제 포인트 혜택 설정
- 고객 상세 확인, 방문 포인트 거래 이력 및 잔액 조정
- 고객 개인정보 및 관련 원장 삭제

분석 API는 관리자 PIN으로 보호하며 브라우저에는 날짜별 집계값만 전달하고 원본 전화번호를 반환하지 않습니다.

## 개인정보 운영 주의

현재 동의 화면은 수집·이용 목적, 수집 항목, 보유기간, 동의 거부 권리, 미성년자 안내, 삭제·철회 요청 경로를 구분해 표시합니다. 동의 문안 버전은 `2026-09-01-v1`로 기록합니다.

실제 매장 운영 전에는 사업자명, 개인정보 보호 책임자/연락처, 처리위탁·제3자 제공 여부, 파기 절차 등 해당 사업장의 전체 개인정보 처리방침을 별도로 확정하고 공개해야 합니다. 이 구현은 개별 법률 자문을 대체하지 않습니다.

## Android APK

이 저장소에는 Vercel의 LOOP 웹앱을 태블릿 전체 화면으로 표시하는 Capacitor Android 셸이 포함되어 있습니다.

Android SDK와 Java가 설치된 환경에서 다음 명령으로 debug APK를 만들 수 있습니다.

```bash
npm install
npm run cap:sync
cd android
./gradlew assembleDebug
```

생성 파일:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

APK는 `https://loop-membership-eight.vercel.app/?loop-connect=1`을 처음 불러옵니다. 이미 연결된 기기는 저장된 토큰을 사용해 연결 화면을 건너뜁니다.

GitHub Actions CI에서도 테스트와 프로덕션 빌드를 실행합니다.
